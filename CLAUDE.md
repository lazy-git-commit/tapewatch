## Architecture

**Full algorithm documentation lives in `docs/algorithm.md`** — every filter,
threshold, and the incident that motivated it. Keep it updated with any rule change.

The system runs four APScheduler background jobs from `main.py`:

**`news_cycle`** (every 1 minute, unconditional):
Session-gated (v21, `market/sessions.py::get_trading_session` — T212 24/5 sessions ET: premarket 04:00–09:30, regular 09:30–16:00, afterhours 16:00–20:00, overnight 20:00–04:00). **regular**: pre-market candidate evaluation (first 30 min) → retry queue → `news/fetcher.py` → `market/price_check.py` → risk gates → `trading/executor.py` (buy + **resting STOP** — v20) → `storage/database.py`. **afterhours** (`AFTERHOURS_TRADING_ENABLED`, **default OFF as of v21.6, 2026-07-27**): same pipeline in the extended regime — anchored session analysis, RVOL band replaced by `EXTENDED_MIN_SESSION_DOLLAR_VOLUME`, ADV$ ≥ `EXTENDED_MIN_ADV_DOLLAR` ($50M), spread ≤ `EXTENDED_MAX_SPREAD_PCT`, `EXTENDED_SIZE_FACTOR` (0.5) sizing, extendedHours market orders, **no resting stop** (T212 stops execute RTH-only; the monitor polls both sides). ⚠️ **Turned off, not just inert**: pre/post-market bars are a Twelvedata Pro/Venture entitlement — our plan 403s every `prepost=true` request, for every symbol — and Finnhub's free quote freezes at the 16:00 ET close, so no extended signal was ever confirmable (0 of 18 trades all-time carry a non-`regular` session). `twelvedata_bars` still latches the 403 on first sight (`extended_bars_available()`) as a defense-in-depth backstop, but the deploy workflow (`.github/workflows/deploy.yml`) now writes `AFTERHOURS_TRADING_ENABLED=false` directly, so entries are off by config, not by a runtime probe. `EXTENDED_HOURS_ENABLED` stays **true** — `is_manage_session` deliberately keeps managing/flattening any position that leaks into the session even with entries off (see its docstring in `market/sessions.py`). Flip `AFTERHOURS_TRADING_ENABLED` back to `true` in the workflow once the Twelvedata plan covers prepost data. **premarket**: scanner builds the at-open watchlist (08:00–09:30 window as before); direct entries only behind `PREMARKET_TRADING_ENABLED` (default off). **overnight/closed**: returns immediately — Blue Ocean (20:00–04:00) is invisible to Finnhub/Twelvedata, so the system is fail-closed there by construction. See docs/algorithm.md §12. Never reschedules its own trigger; rescheduling from within a running job causes APScheduler to silently drop the replacement.

**`monitor_positions`** (every `MONITOR_INTERVAL_SECONDS`, default 5s — v20; early-outs on a local DB query when flat):
**v21 session awareness**: positions are managed in regular hours AND (with `EXTENDED_HOURS_ENABLED`) premarket/afterhours — extended sells carry the `extendedHours` flag, go market-first (the API rejects the flag on limit orders; feature-detected per process via `executor._extended_limit_supported`), and verify their fill instead of assuming it. **After-hours flatten**: everything force-closed `EXTENDED_FLATTEN_BUFFER_MINUTES` (15) before 20:00 ET — past that the tape moves on Blue Ocean, which our data providers don't carry. The ratchet arms the polled breakeven only (no resting re-place) in extended sessions. Everything below is the regular-hours behavior, unchanged:
`monitor/position_monitor.py` manages exits under the **v20 inversion**: the STOP rests at the broker (`stop_order_id`, stop-market, placed at buy time — zero latency on the loss side; realized record: 1 resting-TP fill in 11 trades vs stop slippage −3.4/−3.97/−18.99% under the old polled stop), the monitor notices its fill (order-status + fill-detail check; GONE ≠ filled; status checks throttled to 15s/trade — v20.1) and POLLS take-profit (+5%) and time-stop (60 min), force-flattening everything `EOD_FLATTEN_MINUTES` (10) before the close. **Breakeven ratchet**: at +`RATCHET_TRIGGER_PCT` (2%) the stop is cancelled/re-placed at buy×(1+`RATCHET_LOCK_PCT`/100), once; the armed flag is **persisted on the trade row** (`ratchet_armed`, v20.1 — survives restarts) and set only after the move resolves, so a crash mid-move self-repairs by placing a fresh breakeven stop next cycle; placement failure falls back to a polled breakeven stop. **v21.5 settle period**: not eligible until `_RATCHET_MIN_AGE_SECONDS` (15s) after the fill — HOG (2026-07-23) filled 3.6% off its signal price on a thin book, and one second later the ratchet read that same noisy quote as +3.75%, cancelling the fresh −2% stop and racing its breakeven replacement into a broker 429 (4th T212 order call for the position within one second); the position then sat below its (never-placed) breakeven line for 32 minutes with no resting stop before exiting at the time-stop. The same incident exposed a logging gap — the polled holding-check only logged at DEBUG — now promoted to INFO once per `_PRICE_LOG_EVERY_SECONDS` (60s) per trade so the price the monitor is actually comparing against is provable from the logs. Before any polled sell it cancels the resting order and handles the cancel/fill race (both kinds). Polled sells are bounded LIMIT orders (`SELL_LIMIT_SLACK_PCT`) with market fallback; **v19.2 stuck-exit escalation** — after `_SELL_ESCALATE_AFTER` (3) consecutive unfilled limit attempts for one trade, the next attempt is a market order + one `exit_stuck` system_event. EOD flatten uses a market sell because avoiding overnight gap risk takes priority. Broker reconciliation throttled to 60s and runs BEFORE the flat-DB early-out (v21.2 — an orphan whose failed `open_trade()` left the DB empty must still be found); **v21.2 two-pass confirmation** — a divergence (orphan: broker-open/DB-flat, or phantom: DB-open/broker-flat) fires `CRITICAL` only after surviving two consecutive passes, first sighting is INFO — a mid-cycle fill whose DB commit is still in flight self-resolves by the next pass, while a real divergence can't clear itself (replaces the v21.1 time-based grace window, which also masked a genuinely failed `open_trade()` and ignored the phantom-side race). The monitor's `get_current_price` runs the quote chain fast (single-attempt) with the 390-bar fallback throttled to 30s/symbol (v20.1). Legacy pre-v20 trades with a resting TP (`tp_order_id`) keep the old handling until they close.

**`forward_returns`** (nightly 22:30 UTC): `analysis/forward_returns.py` fills 5/15/60/**120-min and EOD** forward returns for every Claude classification in `sentiment_scores` (yfinance — free, retrospective). This is the prompt-eval feedback loop. **v21.3: the 120m/EOD horizons** were added because the 60-min panel showed the tradeable-catalyst edge (guidance_raise +3.8%/60m, fda_approval +1.1%/60m) still *climbing* at 60 min — i.e. the 60-min time-stop was clipping it mid-move; these columns size the hold on a large sample. `update_forward_returns()` is COALESCE-guarded (a recompute that comes back NULL never clobbers a measured value); `reset_for_extended_returns()` re-opens the recent (in-yfinance-window) rows once to backfill the new horizons, self-limiting via the `_FWD_RETURN_120M_DEPLOYED` cutoff like the anchoring-fix repair. The maturity guard is 125 min (was 65) so the 120-min window is finished before a row is finalized.

**`symbol_map_rebuild`** (daily 08:00 UTC): refreshes the T212 symbol map.

Portfolio risk gates in `main.py` (checked before every entry, re-checked after every fill): daily kill switch (`MAX_DAILY_LOSS_PCT` realized → stand down until tomorrow, fail-closed), `MAX_OPEN_POSITIONS`, `MAX_TRADES_PER_DAY`, 24h per-ticker cooldown. **Entry cutoff (v21.3, `price_check.is_too_late_to_buy`)**: no new position within `ENTRY_CUTOFF_MINUTES` of the session's hard exit boundary — **decoupled from the hold** (`TIME_STOP_MINUTES`) so lengthening the hold to capture the slow catalyst grind doesn't collapse the entry window. `ENTRY_CUTOFF_MINUTES` defaults to the time-stop value (behavior unchanged unless set explicitly). **Session no-quote blackout**: `_no_quote_blackout` (set) + `_no_quote_ticker_strikes` (dict) suppress tickers with no Finnhub/Twelvedata coverage after `_NO_QUOTE_BLACKOUT_RETRIES=2` failed retries — prevents perpetual retry loops that drain credits. **v21.6 scoping**: the blackout asserts "no provider carries this instrument", so only a miss in a session where data is genuinely expected may count — extended-session misses pass `count_strike=False` (our Twelvedata plan has no pre/post bars at all, so an after-hours miss proves nothing about the ticker), and `_reset_no_quote_blackout_if_new_day()` clears it on each new ET trading day. Both fixes come from 2026-07-27, when nine liquid large/mid caps (CDNS, SANM, CLS, KFRC, LOKB, TFII, SJW, SUI, LC) were permanently blacklisted purely for reporting earnings after the bell; the old "resets on service restart" was fiction on a systemd unit that had run six days with `NRestarts=0`.

### Key data contracts

- `news/fetcher.py` fetches articles from Benzinga via massive.com and applies pre-filters before Claude: (1) freshness — older than `max_age_minutes` (3 min during RTH; the session-scoped `_scored_articles` set ensures Claude scores each article exactly once, so the window can exceed the poll cadence with no re-scoring cost — v18); (2) crypto tickers — `X:`-prefixed stripped; (3) roundup articles — >3 tickers skipped; (4) analyst-action headlines (`_ANALYST_ACTION_RE`); (5) **digest/preview headlines (`_DIGEST_RE`, v20)** — "Market-Moving News…"/"Stocks To Watch"/listicles never reach Claude (a 3-ticker digest fabricated "earnings_beat conf=0.8" for three unrelated companies and bought the top of CRCL's 13% spike, 2026-07-10). Remaining articles are scored by Claude Haiku in one batched call: `temperature=0`, rubric in a **cached system prompt**, **forced tool use** (schema-validated output). **v21.7: one retry on an empty result** — a well-formed but empty `classifications` list for a non-empty batch (observed 6-8 cycles in a row, twice, both times the first `news_cycle` tick after a session boundary — 07:00 ET premarket start, 16:00 ET regular→afterhours) is not a parsing failure (200 OK, forced tool use, no per-record validation warnings) and is now retried once at ERROR before giving up; `_mark_scored()` only fires on success, so an un-retried empty batch silently regrows the unscored backlog every cycle until it self-recovers or ages out via `max_age_minutes`. Each article gets `sentiment`, `confidence`, `catalyst_type` (14-class taxonomy — **v20.2: `fda_approval` requires the US FDA specifically**, a non-US regulator such as Health Canada/EMA/MHRA is `other`, so a foreign approval can't dilute the measured FDA edge), `already_moved`. **Every score is persisted to `sentiment_scores`** (eval loop). Positives must then pass code gates to trade: confidence ≥ `MIN_SENTIMENT_CONFIDENCE`, catalyst in `TRADEABLE_CATALYSTS` (**v20 default: `fda_approval,guidance_raise` only** — pruned by measured forward returns; contract_win/earnings_beat/product_launch/ma_target measured negative, see docs/algorithm.md §3.3), `already_moved == False`, magnitude ≥ `MIN_CATALYST_MAGNITUDE`. Produces `NewsItem` dataclasses. **v19.5 same-day cross-reference**: a session-scoped `_ticker_history` dict records every scored article per ticker; the next article for that ticker carries prior same-day verdicts as a `PRIOR ARTICLE(S) TODAY` line in the user message, and the system prompt instructs extra skepticism toward a positive respin of a story that already had a negative reaction that session.
- `market/price_check.py` confirms a signal using a **quote with fallback** (Finnhub `/quote` → Twelvedata `/quote` when Finnhub has no coverage; both yield current price, open, **previous close** `pc`) plus **one Twelvedata session pull + cached daily stats (v20)**. Momentum baseline selected **by timestamp among TODAY's bars only** (`MOMENTUM_LOOKBACK_MINUTES`, staleness guard >10 min; v20 fixed the overnight-gap-as-momentum edge at the open). Rejection filters (in order, with `reason_code`): `opening_block` (5 min), `penny_stock` (< `MIN_STOCK_PRICE` $5), `wide_spread` (last-bar range > `MAX_SPREAD_PCT`), `dead_cat` (< −`MAX_DAY_DROP_PCT` vs prev close), `extended_move` (> `MAX_DAY_MOVE_PCT` 25% vs prev close), `illiquid` (20-day ADV×price < `MIN_DAILY_DOLLAR_VOLUME` $5M — ADV-based, NOT today's volume), `low_momentum` (< `MIN_PRICE_MOVE_PCT`, v15: a 0.2% dead-tape noise floor only), `high_momentum` (> `MAX_PRICE_MOVE_PCT` 15%), `low_volume`/`high_volume` (RVOL band `MIN_RVOL`–`MAX_RVOL`, time-of-day normalized via `compute_rvol`; **v20: session minute-bar volume is the numerator** — the lagging daily bar and the v19.2 rescue are gone; **v20.2: the floor has a size-neutral bypass** — ADV$ ≥ `RVOL_BYPASS_MIN_ADV_DOLLAR` ($50M) plus a held VWAP substitutes for RVOL, since a mega-cap's book is already huge in dollar terms and doesn't need anomalous relative volume to make a real move (BMY 2026-07-13: +2.1% all session, RVOL never exceeded 0.3, rejected on all 27 re-eval cycles because this gate ran before VWAP got a look); the ceiling has no bypass — parabolic volume is the halt signature regardless of cap size), `below_vwap` (price < session VWAP — **v15 size-neutral accumulation test**; gated by `REQUIRE_VWAP_CONFIRMATION`), `overextended` (**v20** — price > VWAP × (1 + `MAX_VWAP_EXTENSION_PCT` 1.5%): with a 2% stop, an entry further above value than the stop is wide gets stopped by routine reversion — LEVI/CRCL; TRANSIENT → re-eval queue = first-pullback entry; validation enforces it stays < `STOP_LOSS_PCT`), `exhausted_bounce` (v19.5 — price already recovered ≥ `EXHAUSTION_RECOVERY_THRESHOLD` of a day's range ≥ `EXHAUSTION_MIN_RANGE_PCT`), `insufficient_data` (v19.2 — no volume measurement AND no VWAP; stacked data fallbacks may no longer approve on a bare quote). **v19.2 data integrity**: quotes older than 20 min (`t` timestamp) are treated as no coverage (`_quote_is_stale`); `low_volume`/`low_momentum`/`overextended`/**`opening_block` (v21.6)** are TRANSIENT — RTH signals re-confirm via a 15-min re-eval queue in `main.py`, premarket candidates stay pending until the window closes. `opening_block` joined the set because it is the only gate that is a pure countdown (guaranteed false minutes later), yet terminal handling discarded eight signals outright — CDNS ×2 (`guidance_raise`, conf 0.88/0.85) died 4.0/4.1 min into a 5-min block on 2026-07-27, sixty seconds short, and earnings/guidance print in exactly that post-16:00 window. **Symbol hygiene**: `clean_benzinga_symbol()` drops foreign-exchange tags (`TSX:` etc.) and disambiguation digits (`INBX1`→`INBX`); the reverse mapping uses `t212_to_symbol()` (exact inverse of the instrument map — T212 re-uses symbols with digit suffixes, e.g. exchange `FLY` = T212 `FLY1_US_EQ`).
- `market/finnhub_bars.py` provides `get_finnhub_quote()` — 3-attempt exponential backoff retry. Primary quote source.
- `market/twelvedata_bars.py` provides `get_session_analysis()` (**v20** — ONE 390-bar 1-min pull → `SessionAnalysis(past_price, current_bar_price, spread_proxy_pct, session_volume, vwap, last_price, session_low, session_high)`, today-only), `get_daily_stats()` (**v20** — `(avg_daily_volume, avg_dollar_volume, prev_close)`, cached per symbol per ET day; failures not cached), and `get_twelvedata_quote()` (Finnhub fallback, normalised `c`/`o`/`pc`/`t`); all take `fast=` (no-retry, for the time-boxed pre-market eval). A typical confirmation costs 1 credit (was 2–3). Two HARD gates run before every HTTP call: (1) **`credits_exhausted()`** — daily backstop at 49,900 credits (Grow plan: no hard cap; backstop is a safety ceiling only); (2) **`_claim_minute_token()`** — thread-safe token bucket, 55 tokens/minute (Grow plan). Either gate returning false skips the HTTP call entirely — no 429 backoff storm. **v21.6 third gate — `_prepost_supported`**: extended-hours bars are a plan entitlement, not per-symbol coverage; the first `prepost=true` 403 latches the capability off process-wide (`extended_bars_available()`), emits a `twelvedata_prepost_unavailable` system_event, and every later extended request short-circuits before any HTTP call. An unrelated 403 (bad key) does not latch. There is no bar-data fallback (Finnhub gives only a quote), so the system fails closed on data unavailability (no bar data → no confirmation → no trade) and keeps scoring news. See docs/algorithm.md §7 "data-budget collapse" and "session no-quote blackout".
- `trading/executor.py` calls the Trading 212 REST API directly. `build_symbol_map()` (retried, rebuilt daily) maps Benzinga symbols to T212 codes. `calculate_quantity()` sizes positions as min(hard cap, risk budget, ADV participation cap, cash); **v21.7**: its `/equity/account/cash` lookup now retries once (2s backoff) on failure — previously a single un-retried 429 on this call killed an already-fully-gated signal outright (ITW, 2026-07-28, on a day with only 2 total 429s). `buy()` retries once on `quantity-precision-mismatch`. `place_stop_loss()` (**v20**, replaced `place_take_profit`) rests a stop-market sell at the broker. `sell()` uses bounded limit orders with cancel-and-retry and market fallback. `get_order_status()` returns `"GONE"` for 404 (filled→history) vs `None` for network errors — callers must never treat `None` as filled. **v21.7**: `main.py::_enter_confirmed` now retries a failed `buy()` once, but only when the failure happened *before* the broker was contacted (`calculate_quantity` error — `order_id is None and quantity == 0` by construction) — a failure after the broker saw the order is never retried, to avoid a double order.
- `premarket/scanner.py` — pre-market watchlist + at-open gap-and-go evaluation (gap band `MIN_GAP_PCT`–`MAX_GAP_PCT` + full standard confirmation). Never pre-places orders. A `conf=None` miss inside `_OPEN_GRACE_MINUTES` (2 min) doesn't burn a no-quote strike (v19.4 — Twelvedata's own snapshot cache commonly isn't rotated for the new session in the first ~90s). `_live_candidates()` returns `(live, graduated)`: candidates still PENDING (never confirmed, never terminally rejected) when the 30-min window closes are **graduated**, not discarded — `main.news_cycle` hands them into the same RTH `_reeval_queue` as an ordinary (non-gap) momentum-confirmation signal (v19.4).
- `storage/database.py` manages a PostgreSQL DB (`DB_URL`) with tables: `news_signals`, `trades` (incl. `stop_order_id` — v20 resting stop — legacy `tp_order_id`, `session` — v21.1, the trading session the entry fired in, for per-session P&L reporting, and **`max_favorable_pct`/`max_adverse_pct` — v21.10 MFE/MAE**, the best/worst unrealised P&L the position reached while open), `portfolio_snapshots`, `sentiment_scores`, `premarket_candidates`, `heartbeat`, `system_events` (v17 degradation/outage markers — TD credit exhaustion, Claude outage/billing/auth, zero-trade drought, **v21.10 `finnhub_outage` + `stale_quote_feed`**; `record_system_event()` derives severity and atomically de-dupes one row per `(event_type, event_day)` via a UNIQUE index + `ON CONFLICT DO NOTHING`). All DB access goes through the `get_conn()` context manager. **MFE/MAE (v21.10)** is written by `monitor/position_monitor.py::_record_excursion` via `update_trade_excursion()` — widen-only in SQL (`GREATEST`/`LEAST`, so it survives restarts and out-of-order writes), gated by an in-process cache so a DB write happens only on a genuinely new extreme rather than every 5s poll, and recorded *before* the exit checks so the peak that fires a take-profit is itself captured. **Pure observability — no exit decision reads these columns.** It exists because the flat time-stop demonstrably cuts live winners (FSS 2026-07-30: exited +0.73%, closed +5.01%) but a trailing-stop replacement could only be backtested over 8 trades (yfinance retains 1-min bars ~30 days), giving +0.51%/trade with a 95% CI of [−0.38, +1.30] — not significant. See CHANGELOG v21.10.

### Configuration

All settings live in `config/settings.py` as a `Settings` dataclass, loaded from `.env` via `python-dotenv`. Import anywhere as:
```python
from config.settings import cfg
```
`cfg.validate()` raises `EnvironmentError` on startup if any API key is missing.

### Ticker detection and blocklist

There is no watchlist — the system relies on Benzinga tagging articles with stock tickers directly. `BLOCKLIST` in `.env` is a comma-separated list of Trading 212 instrument codes (e.g. `TSLA_US_EQ`) to permanently exclude.

### Demo vs live mode

`TRADING_MODE=demo` (default) sends orders to Trading 212's demo API. `TRADING_MODE=live` executes real trades against your Trading 212 ISA. The `cfg.is_live` property gates this in `trading/executor.py`.

### Logging

Logs go to stdout (captured by systemd journald on the VM). Each module uses `logging.getLogger(__name__)`.

### Deployment

Always deploy via `git push origin main`. GitHub Actions picks it up, rsyncs to the VM, and restarts the systemd service. **Never SSH and run commands directly** — changes would be overwritten on the next deploy.

### Test classes

- `TestExitConditions` — take-profit / stop-loss / time-stop logic (no external calls)
- `TestSentimentScoring` — `_batch_score_sentiment()` with mocked Claude responses
- `TestPositionSizing` — `calculate_quantity()` with mocked `_get`
- `TestBuyPrecisionRetry` — T212 precision-mismatch auto-retry logic
- `TestClaudeResilience` — typed Claude failure handling (529 outage → short cooldown, 403 `billing_error` → long cooldown, cooldown suppresses/lifts correctly)
- `tests/test_extended_hours.py` (v21) — session classification against the NYSE calendar (early closes, weekends, overnight boundaries), extended-regime confirmation gates, extendedHours order payloads + fill verification + the limit-capability latch, after-hours flatten / overnight guard / polled-only ratchet
- `TestTwelvedataCreditGuard` — `credits_exhausted()` daily backstop + `_claim_minute_token()` per-minute bucket both short-circuit before HTTP; `fast=` makes one attempt (no 429 backoff loop)

`tests/test_adversarial.py` (v19.3) — chaos suite for every integration seam: hostile payloads (NaN prices, null titles, bare-string ticker lists, mis-scaled Claude confidences, scalar bars) must never crash a cycle nor produce a trade approval. Run it after touching any service-boundary parsing.
